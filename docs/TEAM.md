# HoneyForge — как это работает и как «атаковать»

## Что это

HoneyForge — платформа управления **ловушками (honeypots)** для Blue Team / SOC.
Ловушка притворяется уязвимым сервисом (SSH, FTP, веб-админка). Когда атакующий
её «щупает», система фиксирует это и показывает оператору в реальном времени:
кто подключался, какие логины/пароли перебирал, какие команды вводил.

## Как устроено (просто)

```
  Атакующий ──▶ [ Ловушки ]  ──телеметрия по TLS──▶  Центр  ──▶  Dashboard (вы)
                 Low / Medium     (замаскирован)       (API+БД)     живая лента
```

- **Ловушки** открывают фейковые сервисы и логируют активность.
- **Агент** рядом с ловушкой собирает события и шлёт их в центр **по TLS через
  замаскированный адрес** (выглядит как обычный веб-ресурс, не как «honeypot»).
- **Центр** (API + PostgreSQL) хранит события, считает алерты.
- **Dashboard** показывает ловушки, живую ленту событий, сессии, алерты; умеет
  экспортировать индикаторы компрометации (IoC) в CSV/STIX.

Две ловушки разного «уровня взаимодействия»:

| Ловушка | Что это | Что ловит |
|---|---|---|
| **Low** | Баннеры портов (FTP/telnet/MySQL) | Факт скана/подключения, источник, порт |
| **Medium** | fake-SSH + fake-HTTP админка | Логины/пароли (маскируются), команды сессии, honeytokens |

## Как «атаковать» (3 способа)

> Ловушки намеренно **не выставлены в интернет** (чтобы не приглашать реальных
> атакующих на сервер с другими проектами). Поэтому атака идёт либо скриптом на
> сервере, либо через SSH-туннель.

### Способ 1 — одной командой (весь сценарий сразу)
На сервере:
```
cd /opt/honeyforge && bash scripts/demo-attack.sh
```
Это прогонит: скан Low-ловушки → брутфорс fake-SSH → успешный вход и чтение
honeytoken → попытку входа в fake-HTTP. Через ~10 секунд всё появится в ленте,
а вверху загорятся алерты (brute force + honeytoken).

### Способ 2 — руками через SSH-туннель (самое наглядное)
Со своей машины пробросьте порт fake-SSH и подключитесь как «атакующий»:
```
ssh -L 2222:127.0.0.1:2222 root@93.88.204.70
# в новом окне:
ssh -p 2222 admin@localhost      # пароль: admin123
```
Внутри фейкового «Ubuntu» повводите команды:
```
whoami
cat /etc/passwd
cat /root/.aws/credentials     # это honeytoken — сработает алерт
exit
```
Откройте дашборд — увидите свою сессию, команды и алерт. Клик по событию
сессии покажет детали (введённые креды и список команд).

### Способ 3 — fake-HTTP админка
Пробросьте веб-порт и потыкайте логин:
```
ssh -L 18081:127.0.0.1:18081 root@93.88.204.70
# затем откройте http://localhost:18081/admin и введите любые логин/пароль
```
Попытка входа появится в ленте как `http_request` (пароль замаскирован).

## Что смотреть в дашборде

- **Honeypots** — список ловушек со статусом online/offline и last-seen.
- **Event feed** — живая лента: `scan`, `connect`, `auth_attempt` (с
  замаскированным паролем), `command`, `http_request`, `token_trigger`.
- **Alerts** — срабатывания правил: брутфорс (много попыток входа) и honeytoken.
- **Export CSV / STIX** — выгрузка IoC (адреса источников) для TIP/отчёта.
- Фильтры по ловушке / типу события / IP источника.

## Важно (границы стенда)

Всё синтетическое, изолированный стенд. «Маскировка» — это имитация легитимного
трафика для атакующего внутри стенда, не для сокрытия от владельца. Ловушки не
выставлены в интернет; наружу доступен только дашборд (за паролем оператора).
