# HoneyForge

Централизованная платформа управления ловушками (honeypots) для Blue Team / SOC:
оператор настраивает профили ловушек, разворачивает их на удалённых хостах, в
реальном времени собирает телеметрию атак, хранит и анализирует её. Ловушка
маскирует факт и канал связи с центром, чтобы атакующий не распознал её по
сетевым признакам.

> **Границы стенда.** Только изолированная лабораторная сеть/DMZ. Всё
> синтетическое. «Маскировка» — имитация легитимного трафика для атакующего
> *внутри стенда*, не для сокрытия от владельца инфраструктуры или
> администраторов. Разворачивать — только с письменного согласия владельца стенда.

## Статус

- **Спринт 0 (каркас)** — готово: `docker compose up` поднимает центр + PostgreSQL + Redis + Nginx, healthcheck зелёный.
- **Спринт 1 (центр-ядро)** — готово: Alembic-миграции (авто при старте), JWT-аутентификация оператора с разграничением доступа (RBAC: роль `admin` управляет ловушками и шлёт команды, `viewer` — только чтение), CRUD профилей (FR-C1), регистрация ловушек со статусами (FR-C2), Swagger, seed-скрипт.
- **Спринт 2 (агент + канал)** — готово: агент (enroll/config-pull/beacon) с устойчивым буфером и дослылкой (FR-A3/FR-A4), Low-ловушка с TCP-баннерами (FR-A1), приём телеметрии и выдача конфига (FR-C3), хранение событий с фильтрами (FR-C4) и обогащением страной/ASN источника по офлайн-базе (GeoIP). Канал по TLS (MASK-1) через замаскированный endpoint `/assets/v3/*` (MASK-2); сегментация сетей mgmt/honeynet (MASK-3). Обратный канал управления: центр ставит ловушке команды (`stop`/`start`/`rotate_creds`/`refresh`), агент забирает их в ответе телеметрии, исполняет и подтверждает (ack).
- **Спринт 3 (dashboard + realtime)** — готово: React+Vite dashboard (логин оператора, список ловушек со статусами, живая лента событий по WebSocket, фильтры, top-источники, блок аналитики на Chart.js — события за 24 ч, разбивка по типам, топ источников и стран; в ленте у источника флаг страны и ASN), realtime-слой на WebSocket с подпиской на Redis.
- **Спринт 4 (Medium-ловушка)** — готово: fake-SSH на asyncssh (перехват кредов, интерактивный fake-shell по синтетической ФС, журнал команд), fake-HTTP админка и fake-MySQL (перехват логина и SQL-запросов по MySQL wire-протоколу); материализация сессий и попыток входа на центре с маскированием паролей (FR-A1/FR-A2); деталь сессии в API и UI; скрытность имени процесса агента (MASK-4).

**Все Must-требования закрыты (граница зачёта — конец Спринта 4).**

- **Спринт 5 (Bonus: маскировка + оркестратор)** — готово: джиттер beacon'ов из профиля (MASK-5), анти-фингерпринтинг таймингов баннеров/SSH-аутентификации (MASK-6), оркестратор деплоя ловушки «одной кнопкой» из профиля через Docker API (FR-C6, кнопка в dashboard). По MASK-7 (mTLS) — см. осознанное решение в DESIGN §8.
- **Спринт 6 (Bonus: алерты + IoC + honeytokens)** — готово: пороговые алерты (брутфорс по порогу попыток, срабатывание honeytoken) с realtime-пушем и панелью в dashboard (FR-C7); экспорт IoC в CSV и STIX 2.1 (FR-C7); honeytoken-canary (fake AWS-ключ) с фиксацией `token_trigger` при доступе (FR-A6).
- **Продвинутые возможности (сверх ТЗ)** — готово:
  - **Корреляция атакующих + MITRE ATT&CK:** события/команды авто-размечаются по ATT&CK; центр связывает одного атакующего через весь парк ловушек и считает threat-score (`/attackers`, панель + модалка в UI).
  - **Адаптивная лестница обмана:** при high-алерте (брутфорс/honeytoken) платформа авто-разворачивает decoy-ловушку через оркестратор (с лимитом и дедупом; `/deception`, панель в UI).
  - **Само-детекция «ловушку спалили?»:** обнаружение recon-за-мониторингом (ps/netstat/детект VM/поиск honeypot) → алерт `honeypot_probe` + авто-ре-маскировка (ротация имени процесса, агент переприменяет на лету).
- **mTLS с pinning и ротацией (Bonus MASK-7)** — готово (toggleable): взаимный TLS на агентском канале с клиентскими сертификатами, подписанными локальным CA; агент пинит CA и ротирует сертификат перед истечением. Клиентский сертификат требуется только на агентских путях (`ssl_verify_client optional`), поэтому обложка-CDN и маскировка (MASK-2) сохраняются. Включается оверлеем `docker-compose.mtls.yml`; по умолчанию выключен. Подробно — DESIGN §8.
- **High-interaction (Bonus FR-A5)** — готово (lab-only): fake-SSH, где команды атакующего выполняются **по-настоящему** в одноразовой, сетево-изолированной (`--network none`) песочнице с лимитами ресурсов и авто-уничтожением (auto-reset). Полная запись сессии, команды как high-severity события; файлы, занесённые атакующим в песочницу (напр. дроппер), захватываются и передаются в центр — оператор видит их в панели Artifacts и скачивает. Требует Docker-сокет на хосте ловушки — **только для изолированного стенда**. Включается оверлеем `docker-compose.high.yml` (комбинируется с dev или prod; нужен `SEED_HIGH_ENROLL_TOKEN` в `.env`); порт fake-SSH — только на `127.0.0.1`.

Dashboard: открыть `http://localhost:8080`, войти оператором. Лента обновляется
в реальном времени; клик по событию сессии открывает детали (креды + команды).
Порты-приманки Medium: `2222`→22 (fake-SSH, `admin`/`admin123`), `8081`→80 (fake-HTTP admin).

## Стек

Python 3.12 / FastAPI · PostgreSQL 16 · Redis 7 · Nginx · React+Vite (dashboard) ·
docker-compose.

## Быстрый старт (Спринт 0)

```bash
cp .env.example .env              # при необходимости отредактируйте секреты
docker compose up --build         # всё остальное — автоматически
```

Одна команда поднимает весь стек: `cert-init` генерирует self-signed TLS-сертификат,
центр применяет миграции и засевает оператора/профили/ловушки, а контейнеры
`honeypot-low` и `honeypot-medium` сами регистрируются и начинают слушать порты-приманки.
Проверить сценарий «атака → событие»:

```bash
# «атакующий» подключается к Low-ловушке (host 2021 -> honeypot tcp/21)
printf 'USER root\r\n' | nc localhost 2021
```

Событие появится в `GET /api/v1/events` в течение beacon-интервала (~10 c).
Порты-приманки на хосте: `2021`→21 (FTP), `2023`→23 (telnet), `23306`→3306 (MySQL).

Проверка готовности:

```bash
curl http://localhost:8080/healthz
# {"status":"ok","checks":{"postgres":"ok","redis":"ok"}}
```

- `http://localhost:8080` — операторский контур (Control API; Swagger — `/docs`).
- `https://nginx:8443` — замаскированный публичный контур (приём телеметрии по TLS через `/assets/v3/*`). Слушает **только внутри сети honeynet** и на хост по умолчанию не публикуется; агенты ходят на него изнутри.

Seed выполняется автоматически при старте центра (идемпотентно). Запустить вручную:

```bash
docker compose exec -e PYTHONPATH=/app center python scripts/seed.py
```

Логин оператора (по умолчанию `admin` / значение `SEED_OPERATOR_PASSWORD` из `.env`):

```bash
curl -s -X POST http://localhost:8080/api/v1/auth/login \
  -d "username=admin&password=honeyforge-admin"
```

Миграции применяются автоматически при старте контейнера `center`
(`alembic upgrade head` в entrypoint).

Остановить: `docker compose down` (данные БД сохраняются в томе `pgdata`;
`docker compose down -v` удалит и данные).
